# Hosted advisor assessment

The captured reports contain two unchanged Auth configuration warnings (leaked-password protection and insufficient MFA options). Performance warnings changed from three multiple-permissive-policy findings to eleven such findings plus nine `auth_rls_initplan` findings. No ERROR-level finding was reported. `advisor-review.json` identifies all new performance findings; the original reports are preserved as UTF-8 JSON.

The nine initplan findings concern transaction-local `current_setting` reads in exact public-slug/root-lock scope, five public tenant-scoped relation reads, exact profile-target sharing facts and profile-target locking. These settings are supplied by the trusted API transaction. They are storage boundaries, not browser-controlled claims or replacements for API audience decisions. The expressions compare slug, tenant or user selectors; actual application queries also constrain their operation targets. Re-evaluating a setting can add CPU cost when many candidate rows are scanned. The small existing hosted dataset does not establish performance at scale. Supabase recommends statement-level initplans for row-independent policy inputs: [RLS performance guidance](https://supabase.com/docs/guides/database/postgres/row-level-security#call-functions-with-select).

The eleven multiple-policy warnings identify intentional alternative `ct_api` scopes: self, command/tenant, public exact-target, global-profile facts and row-lock access. PostgreSQL combines permissive policies with OR; independent restrictive archive policies still apply. A blanket AND consolidation would change access, and merely merging the OR expressions would not prove lower cost. Column grants, fixed HTTP projections, policy decisions and G-02 retain separate responsibilities. The catalog matches the reviewed local catalog and exact runtime manifest; external application grants remain empty.

Assessment: performance follow-up, not a discovered authorization regression or failed migration. Retain the reviewed scopes and G-02. Before a scale-sensitive release or expanded query family, benchmark representative tenant/profile cardinalities and examine actual plans, then separately review any row-independent initplan optimization against every runtime audience and concurrency gate. No scale benchmark, warning remediation, Auth-setting change or database policy change is claimed here. The advisor gate is review and assessment; it does not require silencing every warning.
